# M17 — A transport for lockstep

Eight commits on `m17-transport`, 30 files, +2444/−105. Decided by
[ADR-0017](../adr/0017-lockstep-transport.md). Closes the last item
[ADR-0014](../adr/0014-deterministic-lockstep.md) deliberately left open.

## What this milestone was for

ADR-0014 designed deterministic lockstep and shipped **no transport**, recording five criteria
instead of resolving them. Two were the owner's and were answered on 2026-09-19; the other three
were questions of evidence, and the evidence settled them more sharply than expected.

**The consumer question, put honestly, because M16 taught what it costs not to.**
`docs/DEFERRED.md` recorded the transport as *"Picked up when two machines need to play, which no
consumer needs today"*, and nothing about that changed. What differs is that here **the proof is
the consumer**: an in-memory link never loses a packet, never refuses a connection, and never has
a process die on the other end, so it cannot show what ADR-0014's design does when any of those
happens. Two processes agreeing hash for hash over a socket can. That is a weaker consumer than a
game and a stronger one than none, and the entry is closed saying its trigger never fired.

## The choice made itself

Two of three candidates were eliminated by criteria this project wrote down **before it knew
which candidates existed**, which is the strongest kind of criterion to have.

**GameNetworkingSockets** fails criterion 2 on its own manifest: `"supports": "!uwp & !(arm64 &
windows)"`, and Windows is tier one here. Independently it would have taken the manifest from
seven packages to eleven — openssl, protobuf, abseil and a host protoc build — for
encryption and traversal the scope decision declined.

**SDL3_net** fails criterion 1: it is *"a simple, cross-platform wrapper over TCP/IP sockets"*,
not a reliable ordered channel. Its apparent cheapness is inverted — one already-pinned
dependency, an include prefix already covered — because it is **the only candidate needing a
`net → platform` edge**, which `cmake/ModuleGraph.cmake` forbids by name. The real price is not
the six files that would change: it is that the one module in the graph which is pure state
exchange would acquire the engine's heaviest presentation dependency in order to obtain a socket.

**ENet costs no module-graph edge at all.** The clearest measure of the choice is what did not
change: `ModuleGraph.cmake`, the mermaid diagram, and CLAUDE.md's SDL rules are all untouched.

### The licence was read, not assumed

The port declares **no licence field** and defers to the upstream `LICENSE`, and no ENet tarball
existed in this checkout — so "ENet is MIT" was general knowledge rather than something this
repository could check.

Verified by fetching the exact archive the portfile pins and confirming its **SHA512 equals the
portfile's value**, so the bytes read are the bytes vcpkg builds. `LICENSE` is the standard MIT
text, `Copyright (c) 2002-2024 Lee Salzman`. Both hashes are in ADR-0017 so the next reader can
repeat it. The rule that establishes: **a dependency whose licence this repository has not read
does not enter a GPL-3.0 project.** It cost ten minutes.

## The defect the milestone opened with

`kMaxMessageBytes` was 8 MiB against `CommandInbox::kMaxBytes` of 1 MiB **total across every
message waiting** — so a single message between the two was legal to encode, legal to send, and
tripped a sticky, session-fatal overflow at the far end. The loopback never built messages that
large, so nothing covered it, and it would have become reachable on the first real socket.

A `static_assert` now ties them. Planning also found a **second** disagreement, fixed in prose
rather than numbers: `kMaxCommandsPerTurn` times the command queue's payload ceiling permits a
turn of roughly 256 MiB, so **the binding constraint on a turn is the message cap and not the
command counter** — a producer filling the count with large payloads is refused by the encoder
rather than by the ceiling it would expect.

## The seam, and why the loopback tests are the proof of it

`LinkEnd` holds a `Link*` instead of a `LoopbackHub*`: **four virtual calls**, which is exactly
what it already asked of the hub before M17 gave the asking a name. `broadcast` is deliberately
not one of them — it is a loop over `send`, so one implementation serves every backend.

`Session::create(LinkEnd, SessionConfig)` did not change, and `session.hpp` no longer includes
the loopback at all. **Every existing net test passed unchanged**, because none of them names
`LinkEnd` — they bind ends with `auto`. The one line that did change was an `#include` in
`test_session.cpp`, which had been getting `LoopbackHub` transitively; that is a latent bug the
seam exposed, not an accommodation.

`test_link.cpp` is a second `Link` implementation that records and delivers nothing, because **an
interface with one implementation is a claim rather than a seam**.

## Both ways a peer can vanish

A hub **says goodbye in its destructor** rather than just closing, since dropping the socket
silently would leave every peer waiting ten seconds to learn something it could be told at once.
A process killed outright cannot do that, so **the deadline in `pump` covers it instead**.

The first draft had only the graceful case. It failed, which is how the gap was found, and both
are now tested with the comment saying why neither replaces the other.

**The deadline lives in the transport.** `sim::TurnGate` still reads no clock, so ADR-0014's
central invariant is intact rather than merely respected. Dropping a quiet peer and continuing is
deferred with its reason: a drop is simulation-visible, so every remaining peer would have to
apply it at the identical tick or diverge, and agreeing that tick is a protocol whose subtle
failure is the exact thing lockstep exists to prevent.

## Two processes

The lab gained `--listen` and `--connect`. Both peers reach the same tick at the same hash over a
real socket, and the binary refuses to exit zero if they do not.

`tests/integration/` had never managed two processes. `Session` is written once and every part of
it is a failure mode: the port is waited for with a **deadline rather than a sleep**, a listener
that dies before binding is **noticed rather than waited on**, and **both processes are killed on
every exit path** — a test that raises while a peer holds a port makes the next run fail for an
unrelated reason.

Three cases: they agree; a pair does not reach a solo run's hash; and a killed peer ends the
other's session rather than hanging it. **Verified the first can fail** — making the hub drop
what it receives takes it from exit 0 to exit 1.

## Measurement

The prediction was committed in `d6587f3` with no numbers in the tree. **22.4 µs median against
a predicted 20–100 µs**, and the failure mode it named — ENet's own pacing pushing the answer
into milliseconds — did not happen.

**After four wrong predictions in three milestones, this is worth recording as plainly as the
misses were.** The reason it held: this one was dominated by system calls, whose cost is a
property of the kernel and well known, while M15's and M16's were guesses about how long
arithmetic and small allocations take on a processor nobody had measured them on.

A round trip is **0.13% of a 16.6 ms tick**. What would have mattered is tens of milliseconds,
which exceeds a tick and turns the input-delay window into a stall — two orders of magnitude away.

## What the milestone got wrong along the way

- **A release-only build failure**, caught by the release preset rather than by CI: `EnetHub::pump`
  used its parameter solely inside an assertion, and assertions compile out under `NDEBUG`.
- **Two bugs in my own test helper**, both found by running it: the `with` block closed the log
  files before the assertions read them, and the temporary files were never unlinked.
- **`listen` did too much.** Writing the tests showed that binding and waiting must be two calls,
  because a caller asking for port zero cannot learn which port it got until the socket exists —
  and needs to know, to hand it to the other side.
- **A decision missing from my own ADR.** `enet_initialize` calls `WSAStartup` and is
  process-wide; CLAUDE.md permits one such object and ADR-0015 made `script::Runtime` the second.
  D10 was added *before* the code rather than discovered during it.
- **Three times a failing build left a stale binary** that ran and printed plausible results. Each
  time the numbers were discarded and the build fixed first.

## Verification

- 942 tests on macOS and in the Linux container; `precheck` and `tools/tidy.sh` clean before each
  commit.
- **All six continuous-integration jobs green on the dependency alone, before anything was built
  on it** — the plan's first job, and it cost one commit where M15 paid three failures.
- One Windows trap handled rather than discovered: ENet does not link Winsock or the multimedia
  timer for MSVC, so seventeen call sites would have failed at link on Windows only.
- Every golden hash byte-identical; the five loopback integration cases unchanged and green,
  which is the proof that the seam did not disturb what it abstracted.

## What is not proved

**That this works between two machines.** Everything here is one machine's loopback interface,
which shares a kernel and never touches a wire. Packet loss, reordering under real congestion,
asymmetric latency and a router in the middle are all untested — and the loopback link's injected
faults stand in for them only in the sense that a rehearsal stands in for a performance. The
input-delay window exists precisely because the real number is unknowable from here.

**That sixteen peers work.** Two is what is proved. `kMaxPeers` is 16 and the handshake is
written for it, but nothing has run more than two processes.

## The next smallest slice

**M17 is complete and this is the stopping point.** With it, ADR-0014's last open item is closed
and the M10–M16 series plus its follow-on are done.

What is genuinely open is no longer a milestone in this list. ADR-0010's own answer stands:
completing these is **not** v1.0, which is declared when a game links the engine, loads data and
runs a deterministic simulation without patching internals. Every deferral recorded across the
series now waits on the same thing — a consumer — and the most honest next question is
whether to start one.

Three items remain recorded and unaddressed: the submodule-versus-baseline gap in the
continuous-integration cache key (M17, recorded and deliberately not fixed here); a string API for
mods, which M16 was supposed to have and did not; and dropping a peer without ending the session,
which needs an agreement protocol.
