# M20 — Chess: the rules library

Four commits on `m20-chess-rules`. Under [ADR-0018](../adr/0018-chess-probe.md); the first
milestone of the chess series with chess in it, and the first to prove the engine against a game
rather than against a survey of what a game would need.

## What this milestone was for

To write the whole of chess as simulation state and one command, against
`atlas::simulation` and nothing else, and to see what broke. The prediction was that nothing
would: chess is integer throughout, a board is a table, a move is a command, and a position is
a hash. That prediction — the eighth of the nine ADR-0018 records — was the one that said where
the owner's hypothesis was *right*, and this is where it was tested for real.

## What was built

**The fence and the five tables.** `apps/chess/sim` links `atlas::simulation`, checked at
configure time by the lab's loop copied rather than shared, and proved to refuse a platform link
before it was committed. Board, state, history, result and players: every field explicit-width,
hashed and saved, each refusing on load what a game cannot reach. A world composes them at the
starting position; a kernel with no systems ticks it and the hash does not move.

**The position.** A seventy-two byte value with a `static_assert` saying so, over which
legality is checked by copy-make. Pseudo-legal generation for every piece; castling with its
three conditions in the generator, because "not through check" is the rule and not a filter; en
passant recorded only when a pawn stands ready to take, so two identical positions do not differ
by a capture nobody can make; four promotions; rights spent by a king moving, a rook moving, or a
rook being taken; a repetition key that ignores the clocks. FEN and coordinate notation as
untrusted input with a length cap.

**The command.** `chess.move` is three bytes. Its handler declines, in this order and before
writing anything: the game is over; the source does not hold the colour to move; the move is not
legal. That order is the point of ADR-0019 — every decline is a result, counted, and every peer
makes the same one. Then it makes the move, resets or extends the history, and asks the endings
in an order that matters: mate and stalemate first, so a mate on the hundredth quiet ply is a
mate, then insufficient material, the fifty-move rule, and threefold.

**The golden.** The Opera Game, thirty-three plies through the kernel to mate, its final FEN
asserted, its world hash recorded beside the two engine goldens. The same game recorded and
replayed through `sim::play` with every checkpoint matching, round-tripped through bytes, and
saved at ply sixteen, loaded elsewhere and finished to the uninterrupted game's hash.

## What the tests got wrong before the code did

Twice, and both are worth recording because both are the kind of mistake a golden exists to
catch.

A test asked a bishop pinned along a file to move along it. A bishop cannot move along a file,
pinned or not; the generator was right and the test now asserts that only the king moves.

The plan wrote the Opera Game's final FEN from memory with an empty castling field. Black's king
never left e8 and black's h-rook never left h8, so black still holds a king-side right and the
FEN carries `k`. The rules said so on the first run and the plan was corrected, not the rules.

Perft matched all six published positions on the first run, at every depth tried.

## Mutation checks

| Mutation | Caught by |
|---|---|
| The game-over check removed | The fifty-move case's king move after the draw — **after a fix**: with the check removed a move after *checkmate* is still declined, because no legal move exists, so the mate case could not see it |
| The turn-order check removed | The two-source case: black's move from white's source applied |
| Legality not checked | The illegal-move case: applied, hash moved |
| The history never reset | The pawn-move case and `validate_world`'s upper bound |
| The fifty-move rule asked before mate | The mate-on-the-hundredth-ply case |
| A platform link added to the library | Configure fails with the fence's message |

## Verification

- 999 tests passed in the debug preset; 48 of them are this library's, 1,692 assertions.
- Format clean; `tools/tidy.sh` clean, with one directory-scoped relaxation of the recursion
  check for perft, following `engine/scene/src`'s precedent and recorded in the same shape.
- Module boundaries and SPDX clean. Both engine goldens and the lab's golden unchanged, which
  is trivially true — nothing under `engine/` changed — and checked anyway.
- Six mutation checks, each caught, one after a fix to the test.

## What is not proved

**The chess golden on three platforms.** Recorded on macOS arm64; the branch's continuous
integration run is the first confirmation, and the test comment says so rather than claiming it.

**Performance.** No benchmark this milestone: perft to the tested depths runs in well under a
second in a debug build, which is an observation and not a measurement. The plan puts a perft
prediction and measurement in M22, when there is an application to put it beside.

**Play.** Nobody has played it. There is no board to see and no way to enter a move except a
test. That is M22.
