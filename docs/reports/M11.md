### Mutation checks

| Mutation | Result |
|---|---|
| Cut text without backing off to a character boundary | caught |
| Treat any high-bit byte as a continuation byte | caught |
| Return the whole limit when the text is exactly the capacity | **survived — see below** |
| Do not forward characters to the overlay | caught |
| Drop a letter from the overlay's key table | caught |
| Never report Command held | caught |
| Never report Control held | **survived on this platform — see below** |
| Report no visible input-method request | caught |
| Remove the gamepad dead zone | caught |
| Drop the dead zone's rescale, so full travel falls short of one | caught |
| Never clear gamepad button edges | caught |
| Do not release held state on disconnect | **survived — see below** |
| Bind two actions to one gamepad button | caught |
| Make Faster wrap round instead of stopping at unbounded | caught |
| Stop the display mode wrapping | caught |

**Three survived, and each says something worth keeping.**

*The capacity guard.* Weakening `<=` to `<` reads one byte past the end of the view. The answer
is identical, and the address sanitiser does not object either, because a view over a
`std::string` has a readable byte at `size()`. It cannot be defended by a test, so it is
defended by a comment at the line where someone would delete it.

*The Control modifier.* This machine's shortcut is Command, so breaking Control changes nothing
here — and breaking Command does fail. The test sends each modifier separately for that reason,
and the Linux and Windows runs cover the half this one cannot.

*Releasing held state on disconnect.* Even with a test that reuses the freed slot, this cannot
be caught: the queries gate on connectedness, and the window system reports a fresh pad's
centred axes when it opens. Both of those are someone else's behaviour — one this file's own
gating, which a later change could reasonably drop, and one undocumented — so the clear stays
with that reasoning written beside it.

## Benchmark impact

**None, and none was expected.** Nothing here runs inside a tick or a draw. The lab's golden
hash is `0xff07ef23a1482ff5` before and after the camera refactor, which is the check that
matters for a change that rewrote three input paths.

The one cost worth naming is `sizeof(Event)`, which grew from roughly 24 bytes to about 76 to
hold the text payload inline. At the existing reserve of 256 events that is about 19 KiB of
per-frame storage, allocated once. The alternative payloads would have cost an allocation per
text event or a dangling view, which is the trade the header now records.

## Remaining risks

1. **No input method was ever exercised.** No runner has one installed, so what is tested is
   that a focused field asks for the candidate list near itself and that clicking away
   withdraws the ask. Whether an operating system honours it is unverified by anything here.
2. **The composition preview is not drawn, by choice.** The overlay library has no composition
   interface and its own window-system backend ignores the event too, so a preedit appears
   where the operating system draws it and is invisible until committed where it does not. On
   macOS that means marked text is not visible while composing. Recorded in `DEFERRED.md`.
3. **No physical controller was used.** Virtual joysticks produce real events through the
   ordinary path and run in the Linux container as well as here, which covers translation,
   slots, edges and the dead zone. They do not cover a real pad's mapping database, a pad that
   reports axes before it reports its type, or wireless disconnection mid-frame.
4. **The macOS permission behaviour is only half confirmed.** The gamepad subsystem is off by
   default partly because enumerating input devices can prompt on some systems. Since the
   correction above, both applications enable it on this machine with a window open and **no
   prompt appears**, which is more than this report originally claimed. Nobody has tested a
   machine where the prompt would fire.
5. **`sample_camera_input` has no unit test.** Only the platform may write an `InputState`, so
   a test cannot build one. The arithmetic it feeds is tested; the twenty lines that copy
   fields out of the platform are covered by using the applications and by the integration
   cases, and that is a weaker guarantee stated as such.

## What the gamepad verdict got wrong

**The defect.** `PlatformConfig::gamepad` is off by default, deliberately and for good reasons
written into its own documentation. Neither `atlas_lab` nor `atlas_sandbox` ever set it. So the
platform never initialised the subsystem, never received a connect event, never opened a pad,
and never produced a button or axis. The camera controller's stick branch and the lab's button
routing were unreachable code in both binaries the moment they were written.

**Why nothing caught it.** Every gamepad test constructs its own platform and asks for the
subsystem itself, which is correct for testing the platform and is exactly why none of them
could see this. The integration checks run whole binaries, which is where the gap was visible,
but they asserted on lifecycle lines and had no reason to ask what had been initialised. The
gap was not in any one test; it was between two kinds of test, and nothing looked there.

**What that says about the rest of the milestone.** Everything in the platform was real and
remains so. What was wrong was the sentence claiming a person could pick up a controller and
use it. That claim was made from unit tests plus wiring, without ever running the wired thing,
which is the same error as reporting a benchmark from a stale binary and is the error this
project keeps rediscovering in new forms.

**The fix**, in M12's opening slice. The subsystem follows the window: on when there is one, off
when headless, `--no-gamepad` to force it off. The platform now logs one line naming every
subsystem it actually brought up, and an integration case in each application reads it — the
check that would have caught this, now written. Setting the flag back to false makes that case
fail, which was verified by doing it.
