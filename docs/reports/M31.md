# M31 — Catching up: what M29 and M30 got wrong, before they merge

Four commits on `m31-catch-up`, on top of M30: the record with its predictions, the drop race,
the overlay's layout and drags, and the documents. No new ADR: the race fix is a dated note on
ADR-0017 and ADR-0022, because it changes what "quiet" means and nothing else.

## What this milestone was for

M29 and M30 were done and green, but not merged: the merge had been refused by the permission
system. On 2026-09-29 the owner asked for everything that had gone wrong in them to be caught up
first, and the merge after. Most of what went wrong had been fixed as it happened and is in those
reports — two Windows-only build errors CI found, a benchmark that first measured its own code, a
guard that asked the function it was meant to check, a panel placed in the library's pixels, a
formatting miss, a stale README count. Three things had not been, and each is fixed here.

## What was fixed

**M25's drop race.** CI caught it once in about forty runs, during M30, and until now it was only
flagged. Under lockstep, when one peer dies every survivor stops sending, because none can run a
tick without the dead peer's turn. The socket hub timed each peer by its messages, so a survivor
fell silent about a tick after the dead peer, and whichever timer ran out first decided whether
the listener dropped a live peer with the dead one, or a live peer gave up on the listener. The
margin was one tick on both sides.

The owner chose between two fixes: keep timing by messages and add ordering rules, or **measure
silence by the transport**. The second: a peer is quiet when the hub has had neither a message
from it nor an acknowledgement of anything it sent for the deadline. A peer that is alive keeps
polling while it waits, and ENet's pings are answered by polling; a dead or hung one answers
nothing. The hub asks ENet to ping a quarter of the deadline apart, so a live peer answers several
times within any deadline, a test's 600 ms included. There is no change on the wire.

The consequence, recorded in `DEFERRED.md`: a peer alive and deliberately silent — one paused, say
— now holds the session for as long as it likes, where before it was dropped or ended the session
after ten seconds. Nothing tested either behaviour, and pausing a socket session has no meaning
anyone has chosen.

**The overlay's layout.** M30 drew the overlay at its designed size on the Mac, and the design was
taller than the applications' 1280×720 windows: the scene panel ran to 840, and its Undo row opened
below the edge, where the half-size overlay had fitted. Every panel's first place now ends by
y=700 — the scene panel 380 tall with a 150-point tree, the log console at 500 and 200 tall.

**Drags.** The library takes a drag's speed per pixel, so once M30 made the overlay work in pixels,
a drag on the Mac moved a value twice as far for the same movement of the hand. Speeds are now
given per unit of the layout and divided by the scale the overlay draws at.

**The Windows build rules** M29 tripped over are in CLAUDE.md: the build defines
`WIN32_LEAN_AND_MEAN`, `NOMINMAX` and `UNICODE` itself, MSVC's C4324 wants padding written out,
and Windows-only code is not done until a Windows lane has built it.

## The race, reproduced before it was fixed

A new case in `test_enet_hub.cpp`, "a connector stalled on a lost one is not lost with it", runs
three hubs with the drop policy. Peer 2 is never pumped again, as a killed process is never
scheduled again; the listener and peer 1 keep pumping with nothing to say, as survivors stalled at
the gate do. Against the old hub the listener lost peer 1 as well, and peer 1 ended for want of the
listener — both halves of the race, every time. Against the new one only peer 2 is lost.

## Remaining risks

- **The integration-level race was never reproduced on demand.** The case reproduces the
  mechanism exactly; the three processes did not lose it under load here, and CI's one failure is
  the only time they were seen to.
- **A paused peer holds everyone** (`DEFERRED.md`, M31).
- **The laptop's items still wait for the laptop**: the machine group's first run there, and the
  overlay's interface scaling.
