# M13 — Animation

Completed 2026-09-17. Follows the completion checklist in `CLAUDE.md`. The narrative of what
was built is in the roadmap's M13 section; this is what that section does not carry.

---

## Outcome

| Goal | Verdict |
|---|---|
| Clips that move an entity | **Met.** A module with evaluation, a cache, and one free function. The sandbox's parent root plays an ellipse and a full revolution from a committed file. |
| Clips that change what a sprite shows | **Met.** A frame track over a uniform grid. It cost the renderer nothing: a sprite already carries a rectangle. |
| Two writers on one entity | **Met**, and it is the milestone's point. An entity can be dragged while a clip is moving it; undo takes back the drag and never the animation. ADR-0012. |
| A clip as a file | **Met.** JSON, named, versioned, and treated as hostile input. ADR-0013. |
| Scene format version 2, and the first migration | **Met, with no migration code**, which is the rule rather than the shortcut. See below. |
| Rotation in the renderer | **Met.** The instance grew from 48 to 64 bytes, measured against a prediction written first. |
| The consumer replaced | **Met.** The hand-written animation and the Space key are deleted. |

**Two behaviour changes, named rather than discovered.** Both are improvements and both are
changes, and a reader who notices them later should find them here rather than think they are
regressions.

1. **Pausing and resuming no longer makes the sprite jump.** The old animation was a pure
   function of the tick index, and ticks kept advancing while it was "paused", so un-pausing
   snapped the sprite to where it would have been. The new clock accumulates only while it is
   playing. There is no pause key any more either, because there is nothing left to pause for.
2. **An animated entity can now keep an authored rotation and scale.** `SceneDemo::tick` wrote a
   whole `LocalTransform` brace-initialised with only a position, so it reset rotation and scale
   to their defaults on every animated root every tick — while the inspector's own editor
   carefully preserved both. A scene saved after M13 can hold an authored rotation on an entity
   that previously could not keep one for a frame.

**Slices 1 and 2 recorded their findings and not a tally, which is a gap in my own
record-keeping rather than in the work.** The commits name what each mutation changed; they do
not say how many were run. Later slices state both, and that is the form to keep.

**The one survival was a transposed grid.** Every clip in the tests had a square grid or no
frame track at all, so reading a grid as rows-by-columns instead of columns-by-rows produced the
right answer in every case. There is now a four-by-two clip loaded through the registry and
asserted all the way to the rectangle that reaches the draw path — and the shipped sheet is
two-by-two rather than four-in-a-line for the same reason, so the running application exercises
the row arithmetic too.

**Three findings from slice 2 changed code or comments rather than adding a test.**

- **A test was wrong about its own subject.** It asserted that two keys sharing a time take the
  earlier one. A key at time T is in force *from* T, so the later one wins. The test now says so
  and checks both sides of the moment.
- **A comment claimed something that was never proved.** It said the blend was written
  `(1 - t) * a + t * b` because the usual form is inexact at its end. Swapping them survives
  every test here, so the comment now says the form needs no such argument rather than
  pretending one was made.
- **The speed clamp survived in the default build.** A negative speed converted to unsigned
  saturates to the same answer on this machine. That is undefined behaviour and the sanitizer
  aborts on it, so the test covers the upper half of the clamp in every build and records that
  the lower half is covered by a build rather than by an assertion.

**One assertion was removed in slice 6 rather than kept.** The animation check tested
`awaiting_finalisation` for a clip that decodes and is never claimed — but an asset sitting in
`Decoded` is an asset that is not `Ready`, so the count above it had already failed. It could not
fire. An assertion that cannot fail is decoration.

## Benchmark impact

**The prediction was committed before the change it predicts** (`1fcf4f1`, then `a11ffc1`), so it
is in the history and could not be adjusted to fit.

| Scenario | Before | After | Ratio | Predicted |
|---|---|---|---|---|
| `renderer/quad_batch_submit` 100k | 1580.5 µs | 1903.0 µs | **1.20×** | 1.15–1.35× |
| `renderer/quad_batch_submit` 10k | 256.3 µs | 333.6 µs | **1.30×** | 1.05–1.25× |
| `renderer/allocations_per_frame` | 8 | 8 | — | unchanged |

The larger prediction was right; the smaller was slightly low, because the fixed costs turned out
to be a smaller share than assumed.

**The first measurement said 2.9× and 3.6×, and it was the measurement that was wrong.** The two
sets were taken twenty minutes apart on a machine that was not idle. The "before" minimum was a
lucky run and the "after" set never got one, so comparing minima compared the best luck each set
happened to have. Choosing the minimum had seemed like the careful option and it made the error
larger. The numbers above come from a paired measurement: both binaries built, a cooked shader
directory kept for each, and the two alternated in blocks within the same few minutes.

**The prediction's own threshold is what caught it.** It said that anything past 1.35× meant
finding out why before reporting. Without that line written down in advance, 2.9× would have been
reported as a cost rather than investigated as an anomaly.

**Every golden hash and every headless integration case is byte-identical.** Structural rather
than promised: `animation` cannot link `simulation`, the pose is not serialised, and the lab's
simulation library is fenced at configure time.

## What the format decisions came to

**Scene format version 2 needed no migration code, and that is the rule rather than luck.**
ADR-0007 anticipated this moment and declined to write a migration, on the grounds that a
migration with nothing to migrate is untested by construction. ADR-0012 says why there is still
nothing to write: a version that only *appends* components is read by accepting a range of
versions and branching on none of them, because a component is read when its key is present and
absent when it is not, and a version 1 writer never produced the key. An older file is already a
valid newer one with some components missing.

The rule is asserted rather than described: **a version 1 document loads, re-saves, and equals
itself with only the version number changed.** A change that is not a pure append fails that
test, which is the test telling whoever made it that they now owe a migration.

**A document parser's hostile-input discipline is not the WAV reader's**, and ADR-0013 records
the difference rather than papering over it. That reader checks a declared size against the bytes
actually present *before* allocating. A document parser cannot: by the time any count inside the
document is readable, the whole thing is already in memory. The equivalent bound is on the input
text itself, checked before the parse begins. **The scene reader has the same missing bound and
did not get one here**, because widening that file is a separate change with its own risk; it is
recorded in `DEFERRED.md` with its trigger.

**The asset-payload trigger fired and was declined on purpose.** The plan required this report to
decide rather than let it pass silently. The registry keeps one optional payload per type side by
side in every entry and dispatches by an exhaustive switch; M13 made that four payloads across
five types. It stays, because every edit needed to add a type is one the compiler points at, and
the alternative buys nothing until a payload is large enough to cost something measurable or
something outside this repository needs to add a type of its own. What was missing was not the
generalisation but the *record*: the arrangement had been questioned at three types and at four
and kept both times with the reasoning written nowhere. It is written down now.

## Remaining risks

1. **A clip and the sheet it cuts can disagree, and nothing says so.** A clip written for a
   four-by-two sheet attached to an entity whose sprite is three-by-three shows the wrong frames.
   Import refuses a cell outside the clip's *own* grid, which catches a clip disagreeing with
   itself and cannot catch one disagreeing with a texture it never sees. Accepted knowingly in
   ADR-0013; the fix is an asset dependency graph, which is a change to how every asset is
   requested rather than to clips.
2. **The scene reader still has no cap on its own document length.** The clip reader has one. The
   hole is recorded, not fixed.
3. **Per-sprite texture switching is verified by eye, not by a test.** The draw path binds a
   texture per sprite so the grandchild can use the sheet, and the headless check has no device,
   so nothing automated would notice a regression to one bind per frame — the sheet would simply
   draw as the tile. I confirmed it by rendering the scene and examining the image. A golden-image
   harness is the thing that would close this, and there is none in the repository.
4. **`--anim-check` compares poses to a tolerance, and the tolerance is mine.** 1e-3 is far inside
   every wrong answer available at those sample points — a wrong key, a wrong cell, a clip that
   held instead of looping — but it is a judgement rather than a derivation. The clock is compared
   exactly, because it can be.
5. **Nothing tests the animation at a frame rate other than sixty.** The check drives an exact
   16'666'667 ns step. Frame-rate independence is a property of integer accumulation rather than
   of the step size, and the unit tests vary the step, but the whole-program path does not.
6. **The inspector cannot choose a clip.** It can start, stop, scrub, re-speed, change the loop
   mode and remove an animator, and it cannot say which clip to play, because that needs a file
   picker rather than a widget. Deferred with its trigger.
7. **The audio benchmark from M12 still has no recorded baseline**, so a regression in mixing will
   not be caught by `bench_baseline.py compare`. Unchanged by this milestone and still open.

## Corrections this milestone made to earlier work

- **The shader currency check had been passing by coincidence since M2.** It compares every cooked
  output byte for byte against a fresh build, which is only meaningful when one compiler produced
  both — and it never was: this machine cooks with Homebrew's glslang and CI with the
  distribution's package. Every shader until M13 was simple enough that the two agreed. The first
  shader with real arithmetic in it turned that coincidence into a false failure, on CI, which is
  where it was found. The byte comparison is now gated on the toolchain strings matching and skips
  loudly where they do not; the source hashes, the generated header and the vertex layouts are
  compared either way, because none of them depends on which compiler ran.
- **The vertex attribute offsets were hand-written literals** with nothing cross-checking them
  against the struct they describe. They come from `offsetof` now.
- **The shader cooker never compared a shader's declared inputs against the renderer's layout**,
  although the reflection to do it was already being collected and written into the manifest and
  read by nothing. It does now, on both paths.
- **The demonstration scene had no automated coverage of any kind.** No test ran `--scene`, its
  methods need a graphics device, and nothing here compares images. It has two headless checks now.
- **The edit history's revision counter existed to solve the recomposition problem and was wired
  to nothing.** The sandbox recomposed only at the tail of the animation's tick, which returned
  early while paused — so while paused, dragging an entity changed the authored number, changed
  what the inspector showed, and never moved the picture. The panel even displayed the
  contradiction, and the comment beside that row says it exists so a reader can see which of the
  two disagrees. Nobody had followed it back.
- **The boundary checker could not see the JSON reader**, the one declared dependency missing from
  its third-party prefix list — in the milestone that gave that reader a second consumer.
- **The architecture's time table said `alpha` drives interpolation.** Its only readers pace a
  headless sleep. It now says so, and names the consumer it was added for as deferred.
- **The rotation warning claimed to report once per scene** when its flag is a member and it
  reported once per run. Both the warning and the claim are gone with the limitation.
- **`m_orbiting` was populated, carried through both move operations, declared in the header, and
  read by nothing.**
- **Two of my own serialization tests compared hand-typed documents against writer output**, so
  they were really testing indentation. The migration test now derives its version 1 text from the
  writer, because the claim is about a file this project wrote; a separate case parses a
  hand-written document and asserts what was read.
- **`tile.png` had been committed since M4 with no recorded origin and no known licence.**
  `PROVENANCE.md` said it should be replaced by a generated pattern the next time anything touched
  the sandbox's assets. It was. That file's "third-party or hand-made" section is now empty.
- **The rotated-sprites deferral's stated reason had expired before its trigger fired.** It cited
  the cost per instance byte at a million cells; since M8 the cell field has had its own four-byte
  stream and does not use quad instances at all. The entry says so rather than quietly closing.
- **The loop-mode names and the animator's bounds each existed in two places** by the end of slice
  6 — the serialiser's and the inspector's. Both now live beside the component, because a panel
  must offer what the reader accepts.

## What could not be tested, and why

- **That the animation looks right.** The poses are pinned, the rectangles are pinned, and the
  rotation is pinned through composition. Whether an ellipse plus a revolution reads as pleasing
  motion is not a property any of that captures. I looked at it; that is an observation, not a
  test.
- **The sprite sheet's appearance**, for the same reason, though rather more of it is pinned than
  usual: the cropped screenshot shows the right cell with its marker in the right corner and a
  clean border on all four sides, which is the rectangle being exactly one cell.
- **Frame-rate independence end to end.** See Remaining risks.
