# M16 — Localisation: string tables, English only

Seven commits on `m16-localisation`, 48 files, +3316/−188. Decided by
[ADR-0016](../adr/0016-string-tables.md). The last of the seven subsystems ADR-0010 lifted out
of the charter's exclusions, and the only one whose stated justification turned out to be false.

## What this milestone was scheduled against, and why that mattered

`docs/reports/M15.md` said: *"M15 gives it the first real one, since a mod that adds strings
needs somewhere to put them."* That was checked rather than inherited, and it is not true. M15's
guest interface is eight imports — `atlas_tick`, `atlas_command_type`, `atlas_submit`,
`atlas_random`, `atlas_log` and three view calls — and `atlas_mod.h` declares that the list *is*
the interface rather than a summary of it. None of the eight touches a string table, and a mod
cannot read a file: *"no filesystem, no network, no environment."*

That is not a documentation slip. [ADR-0010](../adr/0010-charter-amendment.md) D6 sets the bar
for all seven subsystems — built when the milestone "has a consumer to build against", dropped
when "no consumer strong enough exists when its turn comes" — and this was the consumer. So the
accounting went to the owner, with dropping the milestone offered as the legitimate outcome the
project's own rule makes it. **The decision was to build.**

**What replaced the justification is duplication that does exist.** The survey found the log
severity words in three independent copies and `speed_name` in two. CLAUDE.md's bar is two real
call sites; this met it twice. It is a weaker consumer than any other milestone in the series
had, and ADR-0016 says so rather than dressing it up.

### The bug the duplication was hiding

The lab's `speed_name` was not a copy. It was **missing the fractional-speed check**, so the lab
reported a half-speed run as `"1x"` on the one row that says how fast time is running. That had
been true since M7. Deleting the second spelling fixed it, which is the entire argument for
having one.

## The decisions worth re-reading

**`std::vformat` is refused outright, and the refusal is enforced rather than asked for.** The
engine's logging path is compile-time checked on purpose, so a pattern read from a file cannot
enter `std::format` at all. The documented escape hatch throws `std::format_error`, which
ADR-0005 forbids crossing a module boundary — and `tools/check_module_deps.py`'s exception
allow-list has exactly one entry, so a `try` in `engine/text/src` fails `precheck` until a second
is written with a reason. A forty-line substituter that cannot throw needs none, and positional
indices would have had to be built on top of `std::format`'s sequential `{}` regardless, because
word order is not English's to fix.

**`edit::Command::label()` returns a key.** It was a display string, a log token and a merge
discriminator at once. That is the drift this milestone exists to remove, and it is what makes
the hardest case tractable: `"Undo {label}"` composes two catalogue entries through the
substituter, with the order of the two left to the translator.

**A missing key returns the key**, counted and logged once. So the catalog may be absent: the
overlay takes a `const Catalog*` and null resolves every key to itself, which means the
absent-catalog path is the same code as the missing-key path rather than a second one nobody
exercises. Every existing test kept working without a registry wired into it, and the 59 GPU
tests — which drive the real overlay on a real device — needed no change at all.

**Loading differs by application, deliberately.** The sandbox requests the table as an asset, so
hot reload covers the interface's own text. The lab reads it through `FileSystem` and
`VirtualPath` exactly as M15 reads a mod, because it has no registry and M12's reason for
declining one still holds. Neither treats a missing table as fatal.

## Four things a test caught that reading would not have

**The duplicate-key refusal could never have fired.** ADR-0016 D7 requires it; the first
implementation was a post-parse scan, and `nlohmann`'s object types collapse a repeated key
*during* parsing. One entry survives, the other is gone, and by the time there is a document to
inspect the evidence has been discarded. The check was written, looked right, and was dead code.
It is now a SAX pass over the same bytes before the document is built, with the stronger and
simpler rule that no object may list a key twice.

**The document size-cap test proved nothing.** It padded one value with megabytes of `x`, which
the value-length check refuses whether the cap exists or not; removing the cap left it passing.
The cap is on the input text before the parse, so the exercising document must have nothing else
wrong — it is now padded with a *comment*, every key, value and count well inside its own limit.

**The digit-cap test proved nothing either.** Unsigned overflow is *defined* to wrap, not
undefined, so `{99999999999999999999}` wraps to something far out of range and is copied through
for the ordinary reason. The real hazard is `{18446744073709551617}`, congruent to 1 modulo 2⁶⁴,
which without the cap would select the **second argument** — a pattern addressing a slot it does
not name.

**`4x` had no assertion.** Making `speed_name` report it as `2x` broke nothing: 1x, 2x and 8x
were checked and 4 was skipped.

All four were found by mutation rather than by review, which is the whole reason the practice
exists. Two were tests asserting something other than what they claimed.

## Mutation testing

Thirty-one mutations across the five slices. Every invariant has one, each named beside the test
that catches it. **Three genuine survivals, all fixed**; three that did not compile, which are
not survivals; and **one survival kept on purpose** — the finaliser's type check is a performance
guard rather than a correctness one, since `take_string_table` returns nothing for an asset with
no such payload. That is a comment to correct rather than a test to fix, and the caveat the clip
cache already carried is now here too.

Two further "survivals" were a harness mistake of mine: the `[panels]` cases live in
`atlas_test_tools_logic` and I ran `atlas_test_tools`. Not survivals — a binary that did not
contain the tests.

## Measurement

`bench_text`'s prediction was committed in `cd92326`, before any number existed, and it was
wrong twice: **7.2 ns a lookup against a predicted 20–60, and 57 ns a substitution against
100–300.** Both too pessimistic, both recorded as wrong rather than widened.

**The first run could not test the prediction at all.** Three scenarios came out at 0, 0 and
42 ns — this machine's timer resolution, and the same floor M15 hit. So two batched scenarios
were added *after* that run, and the ordering is stated in the source and in
[PERFORMANCE.md](../PERFORMANCE.md) rather than hidden. The prediction is not moved: it stands
as committed and is reported against as committed. What changed is that the measurement became
able to test it. **That is the gap M15 recorded against `script/load` and left open; this closes
it rather than repeating it.**

The claim holds with room to spare — about 140 strings a frame at 7.2 ns is roughly a
microsecond, 0.006% of a 16.6 ms frame. And the failure mode the prediction named did not happen:
nothing is near 500 ns, so the transparent hasher is working and a `string_view` finds a
`std::string` key without building one. That was the only outcome that would have needed action.

## The limit this milestone must not overclaim

**A second language is a data change only for Western European languages.** The overlay renders
Dear ImGui's default baked atlas — Basic Latin and Latin-1 Supplement. Nothing in the tree
touches `io.Fonts`, and `imgui` is pinned without the `freetype` feature. French, German,
Spanish and Italian would render from a translated file. Polish, Czech, Turkish, Greek, Russian,
Hebrew, Arabic and every CJK language would show blanks.

Recorded in `DEFERRED.md` with its trigger **before any of the milestone was built**, rather
than discovered after somebody shipped a Polish table and saw boxes.

## Verification

- 919 tests on macOS, `precheck` clean, `tools/tidy.sh` clean and run **before** each commit.
- 59 GPU tests green on a real device, unchanged by the milestone.
- `--text-check`: 130 keys, all resolved; and the same check against a table with one entry
  removed fails and names it.
- Hot reload of the interface's own text, proved end to end.
- Every golden hash byte-identical: `text` is reachable from nothing the simulation touches.

## What is not proved

**That the pixels say "Pause" rather than `ui.sim.pause`.** `--screenshot` needs a graphics
device and the dummy driver has none, so no automated check in this repository reads rendered
text. What stands in its place is the 130-key resolution check, the round-trip test, and both
applications reporting a full load. A reader who wants certainty should run
`./build/macos-debug/bin/atlas_sandbox --scene` and look.

**That `--text-check` covers every call site.** It checks the *keys*, so a key used somewhere
and never added to `text_keys.hpp` escapes it — it would render as itself and nothing would
complain. What stops that is the rule that a call site names a constant and never a string, plus
a grep of the overlay for a literal at an ImGui call, which finds only widget identifiers. That
weakness is written at the check itself.

## The next smallest slice

**M16 is complete, and with it the M10–M16 series.** All seven subsystems ADR-0010 lifted out
of the charter are built. ADR-0010's own answer to what that means stands: completing them is
**not** v1.0, which is declared when a game links the engine and runs without patching it.

[M17 — a transport for lockstep](../../ROADMAP.md) is planned and approved, closing the last
open item ADR-0014 left. Its record takes **0017**, because numbers follow landing order and
this milestone took 0016. Its slice 0 is the `kMaxMessageBytes`/`CommandInbox::kMaxBytes`
reconciliation: a legal message between 1 and 8 MiB is currently impossible to receive.
