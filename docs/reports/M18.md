# M18 — Chess: the record, and M16's hotfix

Two commits on `m18-chess-record`. Decided by [ADR-0018](../adr/0018-chess-probe.md). The first
milestone of the chess series, M18 to M23, and like M10 it is mostly a record: one bug fixed,
one decision written down, and nothing else built.

## What this milestone was for

The owner asked for the first game on the engine, chess, and said what the game was for: *"I
imagine this would surface many bugs within the game engine."* The plan for the series took
that as a hypothesis and did what the project does with a hypothesis — wrote down where it
should bend **before** looking, then looked. Nine predictions; seven confirmed, one half, one
wrong in its mechanism; and three findings nobody predicted. ADR-0018 carries the table.

One of the three unpredicted findings was a regression on `main`, and it is the reason this
milestone has a slice 0.

## The regression M16 shipped

M16 routed every string the overlay shows through `text::Catalog` and reported *"everything the
overlay shows"* as met. Inside the panels that was true. **What a person saw first was not**:
all five panel titles, every statistic label and the display-mode buttons reached Dear ImGui
as their keys, so the lab's window was titled `app.title.lab` and its rows read
`app.stat.frame`. The lab also handed two of its statistic *values* over as unresolved keys —
`ui.speed.1x` on the row that says how fast time is running.

The cause was ordinary: `tr` was defined in an anonymous namespace *below* the first panel
that needed it, so the title and the labels were written without it, and the mode buttons were
written the same way for consistency with the labels. The reason it survived is the interesting
part. `--text-check` resolves every key in `text_keys.hpp` against the table and reported 130
of 130. It checks that keys *resolve*, not that widgets *ask*. Every key resolved; several
widgets never asked. The M16 report's "What is not proved" section had, in fact, named this
class of gap in its second paragraph and then not looked for an instance of it.

**The fix** is a `title_for(catalog, key)` helper producing `"text###key"`: the person reads the
text, and Dear ImGui keeps the key as the window's identifier, so a retranslation does not
forget where the user docked a window. Labels and mode names go through `tr`. The lab resolves
its two values before handing them over, because a value is the application's to compose.

**The test that would have caught it** counts. `Catalog` gains `lookups()` beside `misses()`,
and `engine/tools/tests/test_stats_panel.cpp` draws the statistics panel against a loaded
catalog and asserts **exactly one lookup per key the panel was handed**. `misses() == 0` was
true of the broken overlay too — it never asked — which is why the miss counter alone could not
have been the assertion. A second case draws against an empty catalog and asserts four distinct
misses; a third draws the controls panel with no modes, one mode and two, and asserts the
distinct-miss count steps by two and then by one.

### Mutation checks

| Mutation | Caught by | Note |
|---|---|---|
| `title_for` returns the raw key | `lookups() == 4` fails at 3; empty-catalog case fails at 3 distinct | A first attempt did not compile (unused parameter) and is not counted |
| A label shown raw | `lookups() == 4` fails at 1; empty-catalog case fails at 1 distinct | |
| A mode button from the raw key | one-mode minus no-mode fails at 1 rather than 2 | **Survived the first draft.** The draft compared one mode against two, and the panel also looks up the *next* mode's name to decide whether to wrap, which resolved the second name whether or not the button did. The test now compares none against one, where the first mode has no predecessor and reaches the catalog only through its button. |

A survival is a test to fix, and it was. The draft's error is recorded in the test's own
comment so the next reader does not "simplify" it back.

The M16 report gains a dated correction rather than an edit, per the ADR index's own rule.

## The record

ADR-0018 decides eight things, and the two that matter most are the two the owner was asked
about. **Chess lives in the tree** at `apps/chess/`, as a named exception to
`apps/CMakeLists.txt:3`'s *"not games and not libraries"* — an exception, not a repeal, so the
rule still binds the lab and the sandbox. And **the probe is not v1.0**: the charter's criterion
names a game *project*, in its own repository, and a game inside the tree cannot prove the
public surface is sufficient because it can see everything. What it can prove is that a game
can be written without a line of it reaching `engine/`, and that is the series' exit criterion.

The `runtime` deferral fired — chess is the third application its condition named — and is
answered rather than left firing: not built, count at three, the loops still agree only in
their ingredients. The lift-out to a separate repository and the mod opponent are each recorded
with a trigger.

**The engine changes chess forces are decided before the code that needs them.** A command
that may be declined on world state is ADR-0019 and M19; a session that can finish is ADR-0020
and M21. Both are Proposed in the index and written at their gates. Neither knows what a
bishop is, and both name a consumer the lab already had and worked around.

## Verification

- `tools/precheck.sh macos-debug` clean: format, tidy, module boundaries, SPDX, and 946 tests
  passed. `tools/tidy.sh` ran before the commit.
- The eight `gpu` cases in `atlas_test_tools` green on a real device, including the three new
  ones; the 29 `text` cases green with the new `lookups()` case.
- `atlas_sandbox --text-check`: 130 keys, all resolved — unchanged, and now known to be
  necessary rather than sufficient.
- Three mutation checks, each caught, one after a fix to the test.
- **Every golden hash byte-identical**: nothing here touches the simulation.

## What is not proved

**That the pixels say "Strategy Lab".** The same gap the M16 report named: no automated check
reads rendered text. What stands in its place is one step closer to the screen than before —
the catalog's own count of how many times the panel asked it — and a reader who wants certainty
runs the lab and looks at the title bar.

**Anything about chess.** This milestone built none of it. The predictions are scored against
surveys of the tree, not against a game that exists; M20 is where prediction 8 (nothing needed
for save, replay and hashing) is tested for real.
