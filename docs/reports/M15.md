# M15 — Sandboxed mods

Seven slices, `66ee794..` on `m15-sandboxed-mods`. The sixth of the seven subsystems ADR-0010
lifted out of the charter's exclusions, and **the only milestone in the series that adds a
dependency**.

## What was built

`engine/script`: a WebAssembly sandbox, a loader that refuses before it accepts, two independent
budgets, and `ModHost` — a `sim::CommandSource` that is one mod, with one identifier, which a
guest cannot name. The guest interface is `atlas_mod.h`: eight imports, three required exports,
and a list of what is deliberately absent. The lab loads one through a `mods` mount and runs it
once per tick, before that tick.

The boundary itself is not new. ADR-0009 fixed it in M9 — anything outside the tick reaches state
only by submitting, reads only published state, never executes during a tick — and M14 turned it
into `sim::CommandSource`. M15 is the first untrusted thing on the far side of it.

## The decision, and what changed it

ADR-0015 was asked to evaluate WebAssembly against Lua. It evaluated **three** candidates,
because reading the pinned baseline turned up facts the planning conversation did not have:

- **No WebAssembly runtime exists in vcpkg** — not at our baseline, and not at upstream `master`
  checked the same day. So WASM meant writing and owning the project's first overlay port.
- **Lua 5.5 no longer needs one.** `lua_newstate` takes the string-hash seed as an argument,
  which retires the specific objection ADR-0009 raised against stock Lua. Proved from
  `external/vcpkg/ports/sol2/lua-5.5.diff` inside our own checkout.
- **`luau` 0.729 is in the baseline** — MIT, all platforms, no transitive dependencies, and
  purpose-built for running untrusted user scripts. It had never been in the comparison.

So the cost ordering was the reverse of the original framing: the WebAssembly option was the
expensive one and both Lua-family options were free.

**WebAssembly won on an argument this repository had already made.** `docs/DETERMINISM.md`
forbids libm transcendentals in authoritative code, and under lockstep a mod's decisions *are*
authoritative input. In Lua and Luau, `math.sin` is the host's libm, one call away from a mod
author writing something reasonable. The only defence is removing library functions — and
ADR-0009 had already explained why that cannot be trusted: a demonstration script exercises none
of it. Luau is recorded as a named fallback with a written trigger rather than a rejected
alternative, and the trigger did not fire.

## What the dependency cost, measured rather than forecast

ADR-0015 said owning an overlay port is the standing price of the decision. That price arrived
immediately and is worth recording precisely, because it is the part a future milestone will
want to know.

**Three continuous-integration failures before the dependency did anything useful, and none of
them reproducible locally:**

| Platform | Cause |
|---|---|
| macOS Debug and ASan | WAMR's `version.cmake` writes `core/version.h` into the **source** tree, and vcpkg configures debug and release in parallel out of one extracted source. Two writes, one path. Fixed with `DISABLE_PARALLEL_CONFIGURE`, which ~135 registry ports use for exactly this. |
| Windows MSVC Debug | `C4702`, unreachable code, and it was right: every path through the import loop returned, so the increment could never run. |
| Windows MSVC, both lanes | The public header defaults consumers to `__declspec(dllimport)`, which asks for `__imp_` symbols a static library does not have. Sixteen unresolved externals. |

Only the second was Atlas's own code. **Then nothing**: four further slices, every lane green
first try. The tax looks per-WAMR-version rather than per-change, which is the useful shape.

**Two WAMR behaviours that fail silently**, both found by a test rather than by reading:
`wasm_memory_type_get_init_page_count` reports one page for a module declaring four, and
`InstantiationArgs::max_memory_pages` is ignored with only a log line. A memory cap that silently
does not apply is worse than none, so the limit is read from the module's own bytes by code here.

**And one default that would have hollowed out the design.** Instruction metering is **off** in
WAMR, and the first version of the port did not enable it. ADR-0015's budget would have been
absent rather than enforced — a wall-clock watchdog is exactly the failure mode the record warns
against, and silently having no budget is worse again. Every option in the portfile is now
written down as a decision with a reason, because a future version will default something new on.

## The three proofs

**(a) A recording made with a mod replays on a build that never loads one**, to the same hash,
and the case asserts that no script runtime starts during the replay. This needed no code: it is
ADR-0009 decision 2 paying off exactly as written.

**(b) Two peers running the same mod agree hash for hash** under latency 2 and reordering,
without exchanging one of its commands. Each runs its own instance with the same identifier and
seed. The anti-vacuity half is inside the same case — the run without the mod must end somewhere
else, or the agreement is about an empty simulation.

**(c) A mod that reads a host clock cannot load, and diverges when it can.** The import exists
only for a runtime that asked by a name with "unsafe" in it; the run says so at warning level;
two peers then disagree at tick 16 with the divergence attributed to `step region value`, exit 1.
**That case fails if anybody ever adds a clock to the guest interface for real.**

## What was measured

Full numbers in [PERFORMANCE.md](../PERFORMANCE.md). Prediction committed in `c7695f5`, before
any number existed.

| Scenario | Median | Predicted |
|---|---|---|
| `script/tick_empty` | **0.21 µs** | 1–4 µs |
| `script/tick_submit` | 0.29 µs | +1–3 µs over empty |
| `script/tick_views` | 0.25 µs | within 1 µs of empty |
| `script/load` | 5.1–5.8 µs | 20–200 µs |

**Three of four predictions were wrong, all high, and are recorded as wrong.** The guess assumed
WAMR sets up an execution frame per call; it does not — the environment is created once at load
and reused. Eight mods at sixty ticks a second cost about 0.01% of a frame.

One caveat matters more than the numbers: every figure is a multiple of ~42 ns, the harness's
timer resolution here, so the differences between the three per-tick scenarios are one or two
ticks of that clock. A separate check carries the real information — a guest making **ten**
submits measures 0.71 µs, so a command costs roughly 50 ns and scales linearly. That check is
also what proves these are not measurements of a call that never happened.

## Mutation checks

Ten mutations, eight killed first time.

| Mutation | Result |
|---|---|
| A mod submits as peer zero | Killed |
| The per-tick command ceiling removed | Killed |
| The import allow-list removed | Killed |
| A fresh RNG stream per call, so the counter never advances | Killed |
| The host marks the turn gate | **Survived**, then killed |
| A changed generator, against the currency check | Killed |
| The layout view withheld from the mod | Killed |
| The unsafe clock registered unconditionally | Killed |
| A per-peer mod seed | **Not a mutation**, then killed |
| The mod runs after the tick rather than before | **Survived**, then killed |

**The gate mutation survived because the test was weaker than its name.** "A mod never marks the
turn gate" passed even when the host did mark it, because a `TurnGate` refuses a source it was
never told to expect — so the case was checking that the gate is well behaved, not that the host
is. It now puts the mod in the expectation set, which removes the gate's protection and leaves
only the host's restraint.

**The ordering mutation survived because agreement cannot catch it.** Running the mod *after* the
tick is deterministic, identical on both peers, and a different simulation. Pinned now by the
exact count of commands applied: 58 over 60 ticks at delay 2 means deciding before the tick, 57
means after.

**And one of my mutations was not one.** The first per-peer-seed attempt varied the seed by grid
width — and every peer has the same grid, so nothing varied. Redone at the call site where the
mistake would actually be made: copying the `seed + i` two lines above, which is right for the
synthetic command stream and wrong for a mod.

## Decisions worth finding again

- **The committed `.wasm` is written by a generator, not assembled.** ADR-0015 left this open
  between cooking with a toolchain behind a manifest-and-skip check and writing the bytes here.
  The repository had already answered it twice — uncompressed PNG deflate, hand-written RIFF —
  because a `--check` that compares bytes must compare bytes only this repository decides. It
  costs writing the module in an encoder; it buys a check that means what it says and a mod that
  rebuilds anywhere with no toolchain.
- **The lab gained an asset filesystem**, which it had deliberately refused. The recorded reason
  was proportion: a filesystem "to play one click would be a larger change than the audio module
  itself". A mod changes the proportion, because `VirtualPath` is the only validated way to turn
  a command-line name into a file inside a directory.
- **`script::Runtime` is the second process-wide object in Atlas.** WAMR's initialisation is
  process-global, so the rule bends in one place and ADR-0015 names it.

## Risks and what is not covered

- **No mod bigger than 295 bytes has been loaded.** `script/load` says nothing about a real one.
- **One mod at a time in the lab.** `ModHost` is per-mod and the identifier is a parameter, so
  the mechanism is there; nothing exercises two.
- **The NaN-payload hole remains open**, as ADR-0015 records: WebAssembly does not specify NaN
  payload bits, and a guest could branch on reinterpreted ones. The integer-only boundary does
  not fully close it. Detection is the hash check, which stops the session and attributes the
  divergence.
- **Mods are not in the golden scenario.** The golden hashes are unchanged because nothing in
  them loads a mod; a mod's determinism is proved by the loopback agreement instead.

## Verification

- 869 tests on macOS and in the Linux container, 869 under ASan, 769 under TSan.
- Four workflows green on every pushed commit; six CI jobs including both Windows MSVC lanes.
- Every golden hash byte-identical.
- `tools/precheck.sh` and `tools/tidy.sh` clean.

## The next smallest slice

**M15 is complete and this is the stopping point.** M16 — localisation, string tables, English
only — is the last of the series and the smallest. Its own plan notes it has the weakest call
site of anything in the series: about eighty engineer-facing strings and no text renderer. M15
gives it the first real one, since a mod that adds strings needs somewhere to put them.

Three older items remain recorded and unaddressed: the audio benchmark has no baseline on a
quiet machine (M12), the scene reader has no cap on its own document length although the clip
reader does (M13), and no transport exists for lockstep (M14, by decision).

## Corrected 2026-09-19, while planning M16

Two claims above did not survive contact with the milestone they were about. They are corrected
here rather than edited away, because the sentences are the record of what was believed when
M15 closed, and what changed is worth more than a tidy page.

**M15 did not give M16 a consumer.** The sentence "M15 gives it the first real one, since a mod
that adds strings needs somewhere to put them" describes a milestone that was planned and not
built. The guest interface is eight imports — `atlas_tick`, `atlas_command_type`,
`atlas_submit`, `atlas_random`, `atlas_log`, `atlas_view_count`, `atlas_view_size` and
`atlas_view_read` — and `atlas_mod.h:15` declares that list *is* the interface rather than a
summary of it. Nothing in it touches a string table, and a mod cannot read a file: "no
filesystem, no network, no environment". The only two imports taking a `const char*` are
`atlas_log`, whose lines are engineer diagnostics dropped under load, and
`atlas_command_type`, which resolves an identifier. Giving a mod strings would mean extending
the ABI, widening the untrusted surface ADR-0015 governs, and a materially larger M16.

That matters because ADR-0010 D6 makes it a question rather than a footnote: a subsystem is
built when "its milestone is scheduled and has a consumer to build against", and dropped when
"no consumer strong enough exists when its turn comes". The claim above was the consumer M16
was scheduled against. It was put to the owner on 2026-09-19 with that accounting, and the
decision was to build. **M16's justification is therefore the duplication that exists rather
than the mod that does not**: three independent copies of the log severity words, and two
byte-identical copies of `speed_name`. ADR-0016 carries the accounting.

**The string count was low by about seventy per cent.** "About eighty engineer-facing strings"
counts `engine/tools/src/debug_ui.cpp` alone, where the figure is roughly 73. Adding what the
two applications hand to the overlay and four `to_string` tables under `engine/core`,
`engine/assets`, `engine/scene` and `engine/edit` brings it to **about 135 to 140**. The
milestone is still small; it crosses more module boundaries than the sentence implied.

**Two of the three older items are now closed**, both on 2026-09-19 and both with a wrong
premise recorded against them. The scene reader's document cap landed at `e5e760f`: M13's entry
had never worked out the number, and the number is what decides whether the check does anything.
The audio baseline landed at `854eb0f`: the entry blamed a quiet machine, when the real obstacle
was that a baseline could only be recorded all at once. No transport for lockstep remains open,
by decision, and is M17.
