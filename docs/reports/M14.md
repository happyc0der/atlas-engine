### Mutation checks

| Slice | Run | Caught | Survived |
|---|---|---|---|
| 2 — the gate | 10 | 9 | 1, equivalent |
| 3 — the extractions | 5 | 5 | — |
| 4 — the kernel's refusal | 6 | 6 | — (one after closing a gap) |
| 5 — the wire protocol | 5 | 5 | — |

| 7 — the session | 9 | 9 | — (two after closing gaps) |
| 8 — the proof | 6 | 5 | 1, equivalent |

**Seven mutations found gaps in my tests rather than in the code.** Each is named here because
the test that missed it is now the test that catches it.

- **The gate's progress on re-expectation.** My case retired the floor to exactly the tick the
  peers had reached, so a mutation resetting every source's progress reset them to the value they
  already had. The gap between the floor and the frontier is what makes the property observable.
- **The monotonic floor.** Nothing retired twice, so replacing a maximum with an assignment
  survived.
- **A null gate reporting not ready.** Every case constructed a gate; nothing asked `ready()` of a
  kernel that had none — the function every driver is told to call first.
- **The handshake's field order.** The round-trip compared only the variant index while claiming
  to catch a field read into the wrong member. It compares field by field now, and the mutation
  swapping a seed and a start tick fails two assertions.
- **Poll-based latency.** My case sent before either end had polled, where the receiver's and the
  sender's counts are both zero and indistinguishable.
- **The agreed delay.** My larger proposal came second, where "take the largest" and "take
  whichever came last" agree.
- **The total order.** Sorting by sequence and ignoring the source survived the *entire*
  two-kernel proof, because each peer picked its own cell and the commands commuted. Every tick
  is contested now.

**Two survivals stand, both equivalent.** Removing the gate's early return for an empty
expectation set changes no answer, because `all_of` over nothing is true; the comment says that
now rather than implying the branch is load-bearing. And ignoring a differing hash check changes
nothing inside a run where the hashes agree — disagreement is covered by the session's own tests,
which is stated rather than counted as proved by the lockstep proof.

**And one methodological failure worth recording.** A mutation that removed a constant's only use
failed `-Werror`, and my harness printed nothing — which reads exactly like a pass. A mutation
that does not build is not a mutation that survived. The harness says so out loud now.

## Benchmark impact

**The prediction was committed in `86cdaec`, before any number existed**, as M13's rotation
measurement was.

| Scenario | Median | Per peer | Predicted |
|---|---|---|---|
| `net/gate_and_poll` peers=2 commands=8 | 2.67–2.79 µs | **1.4 µs** | 2–6 µs |
| `net/gate_and_poll` peers=4 commands=8 | 10.6–11.5 µs | **2.7 µs** | 2–6 µs |
| `net/decode_turn` ÷ `net/encode_turn`, 8 commands | — | **1.28×** | 1.5–3× |
| `net/decode_turn` ÷ `net/encode_turn`, 64 commands | — | **1.88×** | 1.5–3× |

**The first prediction was high and is recorded as high.** At two peers the real figure is about
a third below the bottom of the range. What the two rows together show was not predicted at all:
**the cost per peer grows with the peer count**, because each peer broadcasts to every other, so
a session does work proportional to N². Obvious in hindsight, and now written down.

**The conclusion the prediction existed to test stands.** Four peers at sixty ticks a second cost
10.9 µs against a 16.6 ms frame — 0.066%. Lockstep bookkeeping does not need optimising, and that
is now measured rather than assumed.

**Every golden hash is byte-identical**, structurally rather than by promise: a null gate and an
empty gate are both the old path, and the fixed scenario is run with one.

## Remaining risks

1. **There is no transport, so none of this has crossed a machine boundary.** Everything is
   proved in one process over an in-memory link. The link is unkind on purpose — latency,
   reordering, drops, holds, corruption — but it cannot reproduce a real network's failure modes,
   and it shares an address space, a clock and a compiler with both peers. ADR-0014 records the
   criteria for choosing a transport; nothing here should be read as evidence that one will work.
2. **The loopback link is main-thread only.** `CommandInbox` is safe to push into from any thread
   and is tested that way, but nothing yet does. The first transport will be the first real user
   of that property.
3. **A gate with no timeout hangs by design.** A peer that stops reporting stalls the session for
   ever unless something outside changes the expectation set. `PollReport::closed` exists so a
   driver can be told; the lab bounds its own wait so a test fails rather than hangs. A real
   session needs a policy, and does not have one.
4. **The corruption fault often lands inertly**, on a claimant about to be refused anyway or on a
   per-system hash, which is carried for attribution and never compared. The engine-level case
   asserts the property that is true — a corrupted message never produces a *silent*
   disagreement — and the lab's case covers the detected path, where a damaged command always
   changes a cell.
5. **Divergence detection is proved by the session's tests, not by the two-kernel proof.** In a
   run where the peers agree there is no disagreement to detect, which is why a mutation ignoring
   a mismatch survives that file.
6. **The benchmark was taken on a machine at load average five.** Three runs agreed to within
   five per cent, which is enough for a claim about a share of a frame, and is not the standard
   `PERFORMANCE.md` sets for a floor.
7. **A mid-session join is designed for and not built.** Saves already carry per-source sequence
   counters, and `Welcome` exists in the protocol for a handshake with a host that assigns
   identities — which this one does not use. Adding it later is a protocol version change, which
   is why the message is there now.

## Corrections this milestone made to earlier work

- **The replay writer could produce a recording its own reader refused.** `record_commands`
  appended without bound and `to_bytes` wrote without checking, while `from_bytes` refused
  anything past ten million. Written successfully, permanently unloadable — found while surveying
  the file the command codec was lifted out of.
- **`Save::read_header` did not validate the hash algorithm version**, which only `load` did. That
  peek is how a caller decides whether a file is worth opening, and M14's handshake is exactly
  that kind of peek.
- **The replay refused an older recording with the same terse message as a newer one**, where the
  save format has distinguished the two since M6.
- **Divergence attribution reported a falsehood.** It said "no per-system hashes were recorded"
  whenever no system could be blamed — including when hashes were recorded and every one matched.
- **`TickReport` counted a late command and an invalid one as one number.** Under lockstep they
  are opposites: one ends a session, one is something every peer does identically.
- **`SourceId::Local` was hard-coded at two lab call sites**, where it would have meant one peer
  signing another peer's name to its own commands.
- **`animation` had no row in the architecture's ownership table.** M13's debt, paid in the sweep.

## What was built and then removed

Slice 4 gave `CommandSource::poll` a handle binding the turn gate to a single identifier, so that
"mark only your own turn" was unrepresentable rather than documented. It was designed for M15's
sandboxed mod, which does not exist.

The first real implementation wanted the opposite. A lockstep session speaks for **every** peer it
is connected to and must mark all of their turns, so the restriction would have made the interface
unusable by its only user. It was removed in slice 7 and recorded in `DEFERRED.md` with M15's mod
host as the trigger: the constraint belongs at the boundary with an untrusted producer, not in the
interface every producer shares.

Building it was a mistake against this project's own rule — prefer plain code until a real call
site needs the generalisation — and it is recorded here rather than quietly deleted.

## What could not be tested, and why

- **That two machines agree.** There is no transport. Everything here is one process.
- **That the protocol survives a real network.** Loss, duplication, reordering across arbitrary
  delays and a peer that vanishes mid-message are modelled crudely or not at all.
- **That a session between different builds works.** The golden-hash probe is implemented and
  tested against a fabricated mismatch; no two real builds have ever shaken hands.
