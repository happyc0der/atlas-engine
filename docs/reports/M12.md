Nineteen run. Sixteen caught. **Three survived, and two of those were defects in my own
tests rather than acceptable gaps.**

|---|---|

| Accumulate the loop cursor instead of wrapping | **survived, equivalent** |
| Accept any channel count | caught |

| Leak the clip a reload displaced | caught |

| Never report a stalled asset | caught |
| Report a stalled asset immediately | caught |

**The stereo case is the one worth reading.** The test panned hard left, which zeroes the right
output channel outright, so it passed against a mixer that ignored a stereo source's second
channel entirely. It is centred now. The test was wrong, not the code.

**The chunk-bounds case was a memory-safety hole.** A data chunk claiming four billion bytes is
caught by the decoded-size limit even with the bounds check gone, so every existing test still
passed. A chunk claiming ten thousand bytes in a file holding a hundred is not, because ten
thousand bytes of audio is a reasonable amount to decode — and reading it walks ten thousand
bytes past the end of the buffer. That case now exists and runs under the address sanitizer.

**Three more found the same shape of gap.** The metadata chunk in every case happened to be an
even length, so nothing exercised the pad byte a reader must step over. The decoded-size cap
could only be tripped by an input large enough to matter, so it is now tested at seventeen
megabytes rather than assumed. And nothing tested an extensible format chunk at all, so a
reader that stopped at the first tag and decoded a float file as fixed point would have passed.

**Two survivals stand.** Accumulating the loop cursor instead of wrapping is an equivalent
mutation: the cursor is checked once per output frame and advances by one, so it can only ever
arrive exactly at the end. A comment claimed this was guarding against drift over a long loop;
it was not, and the comment now says what the code does. The finaliser's type filter makes the
work proportional to audio assets rather than to all of them, and `take_audio` is what makes it
correct, so deleting the filter changes the cost and not the result — the same arrangement the
texture cache has had since M4.

## Benchmark impact

**Predictions written before the first run, in the benchmark's own header.** Four runs:

| Scenario | Predicted | Measured |
|---|---|---|
| `audio/mix voices=32` | 10–30 µs | **30.7–31.4 µs** |
| `audio/mix voices=1` | under 1 µs | **1.08–1.12 µs** |
| `audio/allocations_per_update` | 0 after warm-up | **0** |

**Two of three were low, and are recorded as low.** The per-sample cost guessed at was about a
tenth optimistic, and since the scaling is linear that error appears at both ends. The
conclusion is unchanged: 31 µs is inside a 100 µs budget and would be inside it at twice the
cost.

**The threading decision measured against real load**, ten seconds of the lab at a million cells
with a sound playing:

| Configuration | Worst frame | Underruns |
|---|---|---|
| 30 ticks a second | 19.7 ms | 0 |
| 60 ticks a second | 70.9 ms | 1 |

The second row is the trade working as ADR-0011 describes rather than failing. That
configuration was already beyond what the tick sustains, by M8's own measurement.

**No baseline was recorded, deliberately.** The machine was not idle: load average around four,
with a browser and a chat client holding the graphics device. Recording writes the whole file,
and the graphics scenarios in the same run were inflated up to 2.7× and varied 4× between runs
of the same binary — one of which came back *faster* than the stored baseline. Nothing in M12
touches the renderer and the audio module has no edge to it.

**Every golden hash and every headless integration case is byte-identical.**

## What slice 0 was for

M11 reported gamepad support as met. Neither application could use any of it:
`PlatformConfig::gamepad` is off by default and no composition root ever set it, so the
subsystem never started, no pad was ever opened, and the camera controller's stick branch was
unreachable in both shipped binaries.

**The gap was between two kinds of test, not inside either.** Every gamepad unit test builds its
own platform and asks for the subsystem itself, which is correct for testing a platform and is
exactly why none of them could see this. The integration checks run whole binaries, where it
was visible, but they assert on lifecycle lines and had no reason to ask what had been
initialised.

The platform now logs one line naming every subsystem it actually brought up, saying "gamepad
off" rather than staying silent, and an integration case in each application reads it. M11's
report and the roadmap verdict are corrected rather than rewritten.

## Remaining risks

1. **Nobody has heard any of this.** The arithmetic is pinned exactly, the real Core Audio path
   opens at 48 kHz stereo float with no conversion, and a pick produces one voice with no
   underruns. Whether a click sounds like a click, and whether the generated ambient loop joins
   to itself without a tick at the seam, is untested and untestable here. The loop is built from
   partials that complete a whole number of cycles over its length, which is the property that
   makes a seamless join, but that is an argument rather than an observation.
2. **No music, by decision.** Ogg, streaming and the incremental decoder are deferred with a
   trigger. The decoder is installed on every platform at no cost, so the deferral is about the
   committed binary fixture it forces, not about the dependency.
3. **The decoded-size limit is a resource cap, not an amplification guard.** Eight-bit audio
   expands four times on decode, which is the worst case, so a file must already be large to
   reach 64 MB. The check that prevents the dangerous case is the chunk-bounds one.
4. **Device loss is not handled.** Unplugging headphones mid-run relies on the window system
   migrating the default device underneath the stream. A device that disappears entirely is
   untested, and there is no event for it.
5. **The audio benchmark has no recorded baseline**, so a future regression in mixing will not
   be caught by `bench_baseline.py compare` until one is recorded on a quiet machine.
6. **`AudioDevice::null()` advances by the wall clock.** It is the only place in the engine
   where audio reads a clock. Harmless, because audio is presentation and is hashed nowhere,
   but it means a null device's voice lifetimes depend on how fast the frame loop runs.

## Corrections this milestone made to earlier work

- **`AssetType::Shader` has been a live enumerator with no finaliser since M4.** An asset
  requested as one decodes, reaches `Decoded`, and stays there forever with the awaiting count
  climbing, nothing logging and nothing failing. The registry now counts and reports that.
- **The first attempt at that check never fired**, because `pump` returned early when no worker
  had finished anything — and a stall is precisely the case where nothing finishes.
- **The error-domain ladder was open-ended at the top.** A code numbered 500 reported itself as
  a serialization error. Both sides of every boundary are now pinned.
- **`CLAUDE.md`'s SDL rule named three places and there were four**; the overlay has used SDL
  types since M3.
- **The architecture diagram called the handle pool a slot map**, a name no type in the codebase
  has ever had.
- **There was no provenance file for any committed binary.** There is now, and it records that
  `tile.png` has been here since M4 with no known origin, which is an admission rather than a
  record.
- **One unrelated function in the file that compiles the image decoder** was enough to make the
  static analyser walk further into the third-party code and report a leak inside it. The
  dispatcher moved to its own translation unit.
