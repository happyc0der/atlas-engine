# M22 — Chess: the application, two people, a socket

Eight commits on `m22-chess-app`. Under [ADR-0018](../adr/0018-chess-probe.md); the milestone in
which the probe became a game somebody can play.

## What this milestone was for

M20 wrote the rules and M19 and M21 gave the engine the two things they needed. What remained
was everything around them: a board a person can see and click, text a person can read, and a
way for two people on two machines to play one game to its end. The question the probe asks
did not change — can a game be written against the engine without a line of it in `engine/` —
and this is where most of the game's lines are.

## What was built

**A board, in one draw call.** `atlas::chess_view` turns a position and a selection into quads
without touching a device: sixty-four squares, the marks, then the pieces, all sampled from one
sheet. Its tests need no graphics device and check what anybody can check on a real board — a1 is
dark, a promotion's four moves to one square get one mark. The layout maps squares to the world
and clicks back in either orientation, half-open at every edge. The piece sheet is generated by
`tools/gen_textures.py` from fill masks with derived outlines, beside the other two textures, and
its byte check covers it.

**Hot-seat play.** Click a piece and its legal moves show; that is a prediction made in the
application so a person is not kept waiting, and the move itself is a `chess.move` command that
reaches the board only through the kernel. `--moves` plays a scripted game and stops with an
error naming the first move the rules decline; `--fen` starts from a position held to
`validate_world` first; `--headless` prints the result and exits. Checked by eye on this
machine's GPU after six moves, with the squares sampled from the captured frame.

**Its own text.** Seventeen keys in `apps/chess/chess_text_keys.hpp`, their words in
`strings/chess.en.json`, loaded beside the engine's table. A status panel shows whose move it is,
the move number, the last move and the result, with labels as keys and values resolved by the
application — the arrangement M18 settled. `--text-check` resolves all seventeen against what is
loaded, and names all seventeen when the table is dropped.

**Two people over a socket.** `--listen` hosts as white and `--connect` joins as black. Who holds
which colour is in the hashed players table before the handshake, so a move from the wrong side
is a decline inside the tick. A side's move is stamped for the next turn it announces, with one
of its own moves in flight at a time; the game ends where the result table is set, both sides
finish the session at that tick, and nothing runs past it. Two processes play Scholar's mate each
knowing only their own moves, and both exit zero at the same position and hash.

## The engine, again

**One engine change, and it was small.** `text::Catalog::add_table` inserts a second table beside
the first, all of it or none, refusing a key already present and a table for another locale. The
M18 surveys had found that an application could own keys already; what it could not do was load
them from a file without replacing the engine's.

**Two extractions, each at its second call site.** The integration helpers and the two-process
session class moved from the lab's check file into `tests/integration/harness.py` when chess
became the second check file. Opening a socket session — `HOST:PORT`, bind or connect, the port
line a harness waits for, the handshake with a deadline — moved from the lab into
`atlas::app_lockstep`, its own library so that an application that plays no session links no
socket library. **That move found a bug**: the lab's port parser never checked that the whole
text was read, so `host:77x` was accepted as port 77. The new test caught it before the code had
moved a line.

**A branch removed rather than kept.** The lab compares a partner's declared finish with its own
`--ticks`, because only the application knows how long a run was meant to be (ADR-0020). The
first draft of chess copied that, comparing against whether its game had ended. For chess the two
games differ only if the states diverged, and then the session already refuses to run past the
partner's finish; the branch could not be reached by any test, so it went, with a comment saying
why at the site.

## Mutation checks

| Mutation | Caught by |
|---|---|
| The chess table not added beside the engine's | `text_check`: all seventeen keys named |
| Black not given to source 1 | `socket_game_to_checkmate`: black's moves declined, no finish |
| A second move of one side in flight | `socket_game_to_checkmate`: the scripts fall out of step |
| No finish on the result tick | `socket_game_to_checkmate`: neither side exits zero |
| Steps run past the result tick | `socket_game_to_checkmate` — **after a fix to the mutation**: its first form also let the recorded result tick move forward, so both sides finished at the same later tick and still agreed; as the single change the bound guards against, it failed three runs out of three |

## Measurement

Predicted first, in `41f02df`: one to five milliseconds for perft to depth three and ten to forty
microseconds a ply. Measured: **172 µs and 1.25 µs**, both about ten times faster than predicted,
for the same reason — a copy-made move costs about 13 ns here, not the hundreds the prediction
assumed. A ply is 0.008% of a frame. `docs/PERFORMANCE.md` has the table and the reasoning.

## Verification

- 1,035 tests passed in the debug preset, including fourteen chess integration cases — nine
  games and refusals from the command line, the text check, three two-process games, and a
  window under the dummy driver — and every lab case unchanged after the harness moved.
- Format clean; clang-tidy 23 clean; module boundaries, SPDX and the texture check clean.
- The release build ran the benchmark three times.
- All three golden hashes unchanged.

## What is not proved

**That two people on two machines can play.** Every socket case runs two processes on one
machine over the loopback interface. Latency between real machines is absorbed by the input
delay by design and is unmeasurable from here, as M17 said.

**That a person enjoys it.** Promotion by click is always to a queen, the status panel is small
on a high-density display because the overlay draws at one pixel per unit, and there is no undo.
Each is recorded in `DEFERRED.md` with its condition.

**v1.0.** By the charter's own letter, as ADR-0018 D2 says: a game inside the tree cannot prove
the engine's public surface is sufficient, because it can see everything. What it proves is that
a game can be written against the command queue, the tables, the hashing, the save, the replay
and the session with nothing reaching `engine/` but two engine changes any game would force and
one small addition to the string catalog.
