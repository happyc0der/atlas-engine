# M30 — The overlay in the window's units

*2026-09-29:* three things this report left open were put right in
[M31](M31.md) before M30 merged: the drop race it flagged, the layout it recorded rather than
changed — which on the Mac was a regression M30 made — and the drags it listed as a risk.

Commits on `m30-overlay-scale`, on top of M29: the record with its predictions, the fix with its
tests and the second GPU run, and the documents with the README's frames remade. No ADR: the
overlay's public API keeps its shape and its units; what changed is that it now honours the
platform's.

## What this milestone was for

On 2026-09-28 the owner asked for everything that needed no Windows machine. M28 had left one
such candidate half-understood — the overlay was small on the laptop's 175% desktop — and reading
the code for it turned up something worse on the owner's own Mac. The platform delivers a pointer
in the window's logical units; the overlay draws in the swapchain's pixels; nothing converted. On
a display of two pixels a point every pointer reached the overlay at half its position, and every
widget was drawn at half the size its layout was written for. The overlay's tests passed, because
they sent each widget's rectangle back to it in the overlay's own pixels.

## What was built

**The overlay converts a pointer, and draws at the density.** `DebugUi` keeps the window's native
handle, through the `platform_internal` target the module graph already listed for `tools`, and
asks it for the pixel density whenever a pointer arrives or a frame begins — never remembering it,
so a window moved to another display follows. A pointer is multiplied into pixels. The style is
rebuilt from the library's one-pixel-a-unit style at that density, the font rasterised at it, and
the default panel positions, sizes and widths, all written at one pixel a unit, scaled with it.
The public API is unchanged: panel rectangles and the input method's request stay in the overlay's
pixels, and `handle_event`'s comment now says which units it takes.

**The tests send what the platform sends.** A helper moves the pointer to an overlay rectangle's
point divided by `Window::display_scale()`, and another begins a frame on a display named in
logical units. A new GPU case checks the log filter field is about nineteen units tall whatever
the density.

**The Linux GPU lane runs twice.** After the usual run, `linux_gpu.sh` sets SDL's X11 scaling
factor to 1.75 — the laptop's display, an interface scaling of 1.75 over one pixel a unit — checks
from the window system's own report that it took, and runs the `gpu` label again. The window's log
line now carries that report as `interface=`, asked of SDL alone, so it cannot be fooled by the
very function it is there to check.

```
window 'Atlas sandbox' created: id=2 logical=1280x720 pixels=2560x1440 scale=2 interface=1     # the Mac
window 'Atlas sandbox' created: id=2 logical=1280x720 pixels=1280x720 scale=1 interface=1.75   # the 175% run
```

## Found on the way

- **My own guard asked the wrong function.** The 175% run first checked `interface=` computed
  through `display_scale()`; with M28's bug put back that read 1 and the run stopped claiming SDL
  had ignored the scaling factor, which was false, before any test could speak. It is now asked of
  SDL alone. Found by the mutation run, which is what the mutation run is for.
- **The tests named their display in pixels.** At two pixels a unit, 1280 by 900 pixels put the
  log console below the bottom of the screen, and the console reported no records at all. They
  name it in logical units now.
- **The default layout does not fit a 720-point window.** The scene panel reaches 840 and the log
  console 790, so the scene's undo row and the log's last lines are off the bottom — in the laptop's
  M28 frame too, and now on the Mac, where the half-size overlay had hidden it. Recorded, not
  changed: the layout is the owner's to choose, and panels move.
- **One panel took the library's default position, which is in pixels.** The statistics panel
  sets no position, so it opened at the library's (60, 60) pixels: 30 points on the Mac, where the
  other panels' positions assume 60. Checking the frames against the laptop's, panel for panel,
  showed it; it now asks for (60, 60) in the layout's units, like the rest.
- **`cmake/ModuleGraph.cmake` said the window handle went "to the renderer and to nothing else"**
  while its own table already listed `tools`. It now says why `tools` has it.
- **The README's frames had no recipe.** They do now, beside them.
- **An intermittent failure in M25's three-peer test, not caused here.** On one CI lane,
  `lab_socket_lost_peer_is_dropped` failed: the relay dropped the peer the test kills and then,
  one tick later, the peer that should have survived. By the log, a survivor blocked at the gate
  on the lost peer goes silent too, and its silence timer expires about a tick after the lost
  peer's; if its first turn after the drop has not arrived, it is dropped as well. It is the first
  such failure in the last forty CI runs. It is a real race in the drop logic, outside this
  milestone, and is flagged as its own task with the log's analysis rather than patched here.

## Benchmark impact

None measured, and none expected: the overlay is not benchmarked, a pointer event gains one query
of the window, and a frame gains the same. The allocation benchmark does not draw the overlay.

## Remaining risks

- **The user's interface scaling is not applied.** On the laptop the overlay is still drawn one
  pixel a unit inside a 1280×720-pixel window. Applying the 1.75 needs the window to grow with it,
  a decision about every application's window, and the laptop to judge (`DEFERRED.md`, M28).
- **Drags are per pixel.** A value dragged in the inspector now moves twice as far per point on
  the Mac as it did when the pointer was unconverted; that is the library's convention, and nobody
  has said it feels wrong.
- **The Mac is still the only real high-density display.** llvmpipe runs at one pixel a unit in
  both passes; the conversion has teeth on the Mac alone, as the display-scale case once had them
  on the laptop alone.
