# Where the committed binary assets came from

Every binary file under `assets/` is either **generated by a script in this repository** or
**listed below with its origin and licence**. A binary with neither is a file nobody can
regenerate, relicense, or explain, and it should not be committed.

This file was created in M12, when the first audio assets arrived. It records what was already
here at the same time, including the one entry that is an admission rather than a record.

## Generated

| File | Generator | Licence |
|---|---|---|
| `audio/click.wav` | `tools/gen_audio_assets.py` | Public domain: integer arithmetic, no source material |
| `audio/ambient_loop.wav` | `tools/gen_audio_assets.py` | Public domain: integer arithmetic, no source material |
| `../cooked/shaders/*.spv`, `*.msl` | `tools/cook_shaders.py` from `shaders/*.hlsl` | GPL-3.0-or-later, as the sources |

Both audio files are checked by `ctest -L lint`, which regenerates them into a scratch
directory and compares byte for byte. A change to a waveform that is not also a change to the
script fails there.

`ambient_loop.wav` is deliberately **not** at the engine's mix rate. It is 22.05 kHz against a
48 kHz mixer, so the real applications exercise resampling rather than only the tests.

## Third-party or hand-made

| File | Origin | Licence |
|---|---|---|
| `textures/tile.png` | **Unknown.** Committed in M4 with no record. | **Unknown** |

`tile.png` is 152 bytes, is used only by the sandbox's demonstration scenes and one scene test,
and is almost certainly a hand-made placeholder. That is a guess, which is the point: nobody
wrote it down at the time, and this table exists so that the next such file is not another
guess. It should be replaced by a generated pattern when something next touches the sandbox's
assets.
